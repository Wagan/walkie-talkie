## Задача A. Структура каталогов

Прикладной код разделён на общую часть и код работ:

```
App/
  Common/
    Inc/  lab.h          (единый интерфейс работы + выбор по LAB_ID)
          trace_swo.h    (SWO/ITM вывод + printf-glue)
          trace_log.h    (TRACE_LOG/TRACE_ERR)
    Src/  trace_swo.c
          bsp_audio_clock.c   (перекрытие тактирования PLLI2S — нужно любой работе со звуком)
  Labs/
          stand_check.c  (LAB00 «Проверка стенда» — бывший audio_loopback.c)
```

Перемещения (через `git mv`, история сохранена):
- `App/Src/trace_swo.c`       → `App/Common/Src/trace_swo.c`
- `App/Inc/trace_swo.h`       → `App/Common/Inc/trace_swo.h`
- `App/Inc/trace_log.h`       → `App/Common/Inc/trace_log.h`
- `App/Src/bsp_audio_clock.c` → `App/Common/Src/bsp_audio_clock.c`
- `App/Src/audio_loopback.c`  → `App/Labs/stand_check.c` (переименование по сути работы,
  а не по номеру: LAB00 — проверка стенда)
- `App/Inc/audio_loopback.h`  → удалён (его интерфейс заменён общим `lab.h`)

### Схема размещения заголовков
Все общие заголовки лежат в одном каталоге **`App/Common/Inc`**, который добавлен в пути
включения (`-I`). Файлы работ (`App/Labs/*.c`) **своих заголовков не имеют** — их внешний
интерфейс задан общим `lab.h` (`Lab_Init`/`Lab_Process`), поэтому отдельный каталог
`App/Labs/Inc` не нужен, и пути включения остаются простыми: добавился ровно один
`-I ../App/Common/Inc` (вместо прежнего `-I ../App/Inc`). Каталоги `App/Common/Src` и
`App/Labs` компилируются автоматически — `App` целиком объявлена папкой-источником
(`<sourceEntries>`), менять источники не потребовалось.

## Задача B. Единая точка входа

Общий заголовок `App/Common/Inc/lab.h` объявляет интерфейс любой работы:
```c
uint8_t Lab_Init(void);    /* инициализация работы; 0 = успех */
void    Lab_Process(void); /* вызывается в основном цикле while(1) */
```
- **Каждый файл работы обёрнут условной компиляцией** по `LAB_ID`: `stand_check.c` — в
  `#if LAB_ID == 0 … #endif`. В сборку попадает код ровно одной работы.
- **`main.c` приведён к общему виду** (только в USER CODE): `#include "lab.h"`, в
  `USER CODE BEGIN 2` — `Lab_Init();`, в `USER CODE BEGIN 3` — `Lab_Process();`. Вызовы
  демо (`AudioLoopback_*`) и heartbeat SWO из `main.c` убраны; ничего специфичного для
  конкретной работы в `main.c` не осталось.
- **Внятная ошибка при неверной конфигурации** — в `lab.h`:
  ```c
  #if !defined(LAB_ID)
  # error "Не задан LAB_ID: активная конфигурация сборки не соответствует ни одной ... выберите конфигурацию работы (напр. LAB00 -> LAB_ID=0)."
  #elif (LAB_ID != 0)
  # error "Для выбранной конфигурации сборки нет кода лабораторной ... Реализовано: LAB00 (LAB_ID=0). Проверьте активную конфигурацию сборки."
  #endif
  ```
  Так при сборке без `LAB_ID` или с номером без кода компиляция падает с понятным
  сообщением (в `main.c`, включающем `lab.h`), а не невнятными ошибками компоновки.
  `lab.h` — единая точка правды по списку реализованных работ; при добавлении новой её
  условие дополняется.

### Сохранение поведения LAB00 (правило 6)
Секундный **heartbeat SWO** («SWO <n>») перенесён из `main.c` в `stand_check.c`
(`Lab_Process`), рядом с существующим статусом демо. Наблюдаемый вывод LAB00 не меняется:
те же строки `SWO <n>`, `[I] status: …`, `[I] audio init OK: …`, та же логика звука,
светодиодов и обработки ошибок.

## Задача C. Конфигурации сборки

### Что изменено в `.cproject` (проверено фактически)
1. Во **всех** конфигурациях путь включения `../App/Inc` заменён на **`../App/Common/Inc`**
   (проверка: `../App/Common/Inc` встречается 3 раза, `../App/Inc` — 0).
2. Добавлена конфигурация **`LAB00`** как полная копия `Debug` (тот же способ, что и у
   штатных Debug/Release):
   - новый уникальный id конфигурации `…config.exe.debug.100000000`, все вложенные
     id инструментов/опций сделаны уникальными (проверено: дублей вложенных id нет —
     `grep id= | uniq -d` показывает только сами id конфигураций и extension-id, что штатно);
   - собственный каталог сборки: `buildPath …/LAB00`;
   - добавлен символ препроцессора **`LAB_ID=0`** (в C-компилятор; встречается 1 раз — только в LAB00);
   - добавлена запись `scannerConfigBuildInfo` для LAB00 (итого их 3).
3. **Сохранены все прежние настройки** — проверено, что в LAB00 (как в Debug/Release) есть:
   include-пути BSP (`Drivers/BSP/STM32F411E-Discovery`) и ThirdParty
   (`ThirdParty/PDM2PCM/Inc`), линковка `:libPDMFilter_CM4_GCC_wc32.a` с
   `-L ../ThirdParty/PDM2PCM/Lib`, символ `USE_STM32F411E_DISCO`, папки-источники
   (`App`/`Core`/`Drivers`). Каждый из этих пунктов теперь встречается по 3 раза (по разу
   на конфигурацию). XML валиден, CRLF сохранён.

> **Важно (правило 8, честно отмечаю):** конфигурация LAB00 создана правкой `.cproject`
> вручную (копированием блока Debug с регенерацией id). XML корректен и структурно
> повторяет Debug, но окончательную проверку даёт только открытие в CubeIDE. Если IDE
> по какой-то причине не подхватит LAB00 — эквивалентный надёжный путь: в IDE
> **Project → Build Configurations → Manage → New… → Copy settings from Debug**, назвать
> `LAB00`, и в её свойствах C/C++ Build → Settings → Preprocessor добавить `LAB_ID=0`.

### Что делать с Debug и Release (предложение, сам не удалял — правило C3)
После раскладки Debug и Release **не задают `LAB_ID`**, поэтому их сборка теперь намеренно
падает на защите из `lab.h` с сообщением «выберите конфигурацию работы» (это и есть
желаемое поведение B4 — не собрать «не ту» прошивку). Они не соответствуют ни одной
работе.

**Рекомендация:** после проверки LAB00 — **удалить** Debug и Release (оставив только
конфигурации работ `LAB*`), чтобы не путать студентов. Пока оставил их на месте; удаление
за владельцем (Project → Build Configurations → Manage → Delete). Альтернатива — оставить
как есть: попытка их собрать даёт понятную ошибку-подсказку.

### Как переключать конфигурации в CubeIDE и где смотреть активную
- Переключить: **Project → Build Configurations → Set Active → LAB00**; либо по маленькой
  стрелке ▾ рядом с кнопкой-молотком **Build** на панели инструментов — выбрать LAB00.
- Активная конфигурация видна там же (галочка в Set Active / выпадающем списке) и по имени
  каталога сборки: собранная LAB00 кладёт объектные файлы и `.elf` в каталог **`LAB00/`**
  (у Debug — `Debug/`, у Release — `Release/`), так что всегда видно, что собрано/залито.
- Отладку запускать при активной LAB00 (конфигурация отладки использует активную сборку).

## Что проверить владельцу перед фиксацией результата

1. Открыть проект в STM32CubeIDE; убедиться, что в списке конфигураций появилась **LAB00**
   (Project → Build Configurations → Manage / Set Active).
2. Сделать **LAB00** активной; собрать. Ожидается: сборка проходит так же, как раньше
   Debug (те же исходники + `LAB_ID=0`), объекты — в каталоге `LAB00/`.
3. Прошить LAB00 в кит и убедиться, что **поведение не изменилось**: звук с микрофона идёт
   на колонки (Fs 16 кГц); зелёный LED4 горит (init OK), синий LED6 мигает (обработка),
   красный LED5 не горит; по SWO идут `SWO <n>`, `[I] audio init OK: …` и `[I] status: …`.
4. (Опционально) проверить защиту: собрать `Debug` — должна появиться понятная ошибка
   компиляции про неверную конфигурацию (`LAB_ID`), а не ошибки компоновки.
5. Решить судьбу Debug/Release (оставить/удалить) — см. предложение выше.

## Дополнение: сообщения компилятора латиницей

Причина: файлы в UTF-8, а консоль сборки CubeIDE читает вывод в системной кодировке
Windows, поэтому кириллица в тексте `#error` показывалась кракозябрами и подсказка была
нечитаема.

Что сделано:
- Тексты **обоих `#error` в `App/Common/Inc/lab.h` переведены на английский** (смысл
  сохранён: не задан `LAB_ID` / нет кода для этого `LAB_ID`, выбрать конфигурацию работы,
  например LAB00). Строки теперь чисто ASCII — читаются в консоли при любой кодировке.
- Проверены все наши файлы в `App/` на другие диагностики компилятора/компоновщика с
  кириллицей (`#error`, `#warning`, `_Static_assert`, `#pragma message`): **других нет** —
  только эти два `#error`.
- Русские комментарии в коде не трогались (они читаются в редакторе нормально).

Формат хранения наших файлов (пункт 4): все 6 файлов в `App/`
(`Common/Inc/lab.h`, `Common/Inc/trace_swo.h`, `Common/Inc/trace_log.h`,
`Common/Src/trace_swo.c`, `Common/Src/bsp_audio_clock.c`, `Labs/stand_check.c`) —
**UTF-8 без BOM**, единообразно по всем файлам. Разнобоя нет; менять нечего.

- Хеш коммита правки: **`c108632c318996b83bed3c4676fe2c5aa2022f6f`** · Push: OK (`0b3a9c2..c108632 main -> main`, exit 0).
