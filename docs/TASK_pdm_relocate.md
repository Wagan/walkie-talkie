ЗАДАНИЕ (Wagan's Team): TASK_pdm_relocate
Автор: Vagan Sarukhanov

КОНТЕКСТ

Сборка проекта walkie-talkie падает: stm32f411e_discovery_audio.h не находит
pdm2pcm_glo.h. Причина установлена диагностикой: перегенерация кода из .ioc физически
удаляет каталог Middlewares/ целиком, потому что CubeMX считает его своей управляемой
зоной, а ни один middleware в .ioc не выбран. Ручная копия PDM жила там же и была
удалена вместе с каталогом.

Файлы целы в коммите df71bd1. Настройки .cproject, сделанные ранее (include-пути,
-L/-l для библиотеки, символ USE_STM32F411E_DISCO), регенерацию пережили. Каталог
Drivers/BSP тоже уцелел. HAL-модули I2S, I2C и SPI включены владельцем через .ioc со
снятой генерацией кода, соответствующие исходники HAL в проекте появились.

Принято решение владельца: вынести PDM2PCM из зоны CubeMX в собственный каталог
ThirdParty/PDM2PCM, а жёстко прописанный относительный include в нашей копии заголовка
BSP заменить на включение по имени с опорой на путь поиска заголовков.


ПРАВИЛА (жёсткие)

1. Не гадать. Все пути и имена проверять фактически.
2. Файл walkie-talkie.ioc не редактировать.
3. main.c и прочий прикладной код не трогать.
4. Проект не собирать — сборку выполнит владелец в IDE.
5. Файлы HAL, CMSIS и всё, что генерирует CubeMX, не править.
6. STOP и вопрос владельцу при любом расхождении или неоднозначности.


ЗАДАЧА A. ПЕРЕНОС ФАЙЛОВ

1. Создать каталог ThirdParty/PDM2PCM в корне проекта, со структурой Inc и Lib.
2. Восстановить из коммита df71bd1 и положить туда:
   ThirdParty/PDM2PCM/Inc/pdm2pcm_glo.h
   ThirdParty/PDM2PCM/Lib/libPDMFilter_CM4_GCC_wc32.a
   Содержимое файлов не изменять. Если восстановление из коммита по какой-то причине
   невозможно — взять оригиналы из Repository, путь указан в
   docs/REPORT_bsp_audio_integration.md, и отметить это в отчёте.
3. Убедиться, что в git не остаётся следов старого расположения: пути
   Middlewares/ST/STM32_Audio/... должны быть удалены из индекса (в рабочем дереве их
   уже нет). Каталог Middlewares не воссоздавать.
4. Проверить контрольные суммы или размеры перенесённых файлов против того, что
   лежит в Repository, и привести сравнение в отчёте.


ЗАДАЧА B. ПРАВКА ЗАГОЛОВКА BSP

В нашей копии Drivers/BSP/STM32F411E-Discovery/stm32f411e_discovery_audio.h заменить
жёстко заданный относительный include PDM-заголовка на включение по имени файла, без
пути.

Требования:
- заменить ровно одну строку, ничего больше в файле не менять;
- над изменённой строкой оставить короткий комментарий на русском: что путь изменён
  относительно оригинала ST, потому что каталог Middlewares вычищается генерацией
  CubeMX, и что файл теперь лежит в ThirdParty/PDM2PCM/Inc;
- привести в отчёте строку до и после.

Проверить, нет ли аналогичных жёстко заданных относительных include на Middlewares в
других скопированных файлах BSP и Components. Если есть — перечислить и поправить тем
же способом, каждую отметив в отчёте.
