Автор: Vagan Sarukhanov

## Цель шага

Убедиться, что переходные платы с модулями DWM1000 подключены к китам правильно и модули
живы. Критерий — чтение по SPI регистра идентификатора устройства и совпадение с паспортным
значением. Радиообмена на этом шаге НЕТ, драйвер DecaWave НЕ переносится.

Обоснование метода — сам мануал: DW1000 User Manual v2.17, §7.2.2 «Register file: 0x00 –
Device Identifier» прямо называет этот регистр идеальным для проверки со стороны хоста, что
интерфейс SPI работает, и рекомендует хосту убедиться в ожидаемом значении, прежде чем
пользоваться микросхемой.

## Факты из документации (не пересчитывать, не гадать)

- **DEV_ID продукционного DW1000 = `0xDECA0130`** (UM §7.2.2). Поля: RIDTAG = 0xDECA
  (биты 31–16), MODEL = 0x01 (биты 15–8), далее VER и REV.
- **Октеты выдаются младшим вперёд** (UM §7.2, вводная часть описания карты регистров).
  То есть при чтении четырёх байт по адресу 0x00 на шине ожидаются `30 01 CA DE`.
- **Неиспользуемые и зарезервированные регистры при чтении возвращают `0xDEADDEAD`**
  (UM §7.2, там же). Это полезный различитель: такой ответ означает, что SPI работает, но
  адрес не тот.
- **Формат транзакции чтения** (DW1000 Datasheet §5.8, Figure 24): первый октет — бит 7 = 0
  (чтение), бит 6 = 0 (без суб-адреса), младшие 6 бит — адрес регистра. Для DEV_ID первый
  октет равен `0x00`, затем тактируются 4 байта данных.
- **SPICSn держать низким всю транзакцию.** Если CSn поднимется между октетами, транзакция
  обрывается, и следующий октет трактуется как заголовок новой (DW1000 Datasheet §5.8.2).
- **Потолок частоты SPI зависит от состояния.** В состоянии INIT, куда модуль приходит после
  сброса, SPICLK не должен превышать **3 МГц**; 20 МГц допустимы только после захвата CLKPLL
  (DW1000 Datasheet §6.1, Table 23 и §5.8.2, Table 18).
- **Режим SPI 0.** Выводы GPIO5/GPIO6 модуля не подключены и внутренне подтянуты вниз, что
  даёт режим 0: CPOL = 0, CPHA = 0.
- **Порядок бит — старшим вперёд** (DW1000 Datasheet §5.8).

Мануалы и даташиты лежат в соседнем проекте: `C:\Users\user\STM32CubeIDE\workspace_1.16.0\
mks-firmware\docs`. Проверять по ним, не по памяти.

привести в отчёте.

### 3. Что делает работа

При старте: перевести CSn в высокий уровень, выдержать сброс модуля (RSTn вниз, затем
отпустить в высокоимпедансное состояние), дать модулю выйти в рабочее состояние, вывести
баннер. Длительности сброса и ожидания взять из даташита модуля (DWM1000 Datasheet, Table 1)
и из DW1000 Datasheet §5.6 — конкретные числа не выдумывать.

Консоль — USB CDC, как в остальных работах. Набор команд минимальный:

- `help` — список команд;
- `devid` — прочитать регистр 0x00 и напечатать сырые четыре байта в порядке приёма,
  собранное 32-битное значение и вердикт: совпадение с `0xDECA0130`, либо `0xDEADDEAD`,
  либо иное;
- `dwreset` — повторить процедуру сброса модуля;
- `spistat` — напечатать фактическую частоту SCK (вычисленную из тактовой шины и делителя,
  а не константой) и настройки CPOL/CPHA.

Частоту SCK на этом шаге держать **не выше 3 МГц**. Частоту шины APB, на которой сидит SPI4,
брать из конфигурации тактирования проекта, а не по памяти; делитель подобрать под этот
предел и зафиксировать расчёт в отчёте.

Вывод в консоль — только ASCII/английский (§4 п.7). Комментарии в коде русские можно.
Копирайт в шапке файла по §4 п.6.

### 4. Диагностика в помощь владельцу

В выводе `devid` при несовпадении печатать короткую подсказку, чем отличаются типовые случаи:
все нули, все единицы, `0xDEADDEAD`, мусор. Толкование этих случаев не выдумывать сверх того,
что следует из фактов выше — достаточно напечатать сырые байты и назвать ожидаемое значение.

### 5. Сборка и коммит

Собрать конфигурацию LAB09 до чистой сборки (0 ошибок, 0 предупреждений) по §4 п.4. Затем
commit + push, хеш вписать в отчёт.
