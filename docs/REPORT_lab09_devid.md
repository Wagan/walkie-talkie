## 4. Расчёт делителя SPI

- Тактирование (из `SystemClock_Config`): HSE 8 МГц → PLL (M=4, N=192, P=/4) → SYSCLK 96 МГц;
  `APB2CLKDivider = HCLK/1` → **PCLK2 (APB2) = 96 МГц**. SPI4 сидит на APB2.
- Потолок SPICLK в состоянии INIT (после сброса) — **3 МГц** (DW1000 UM Table 1).
- Выбран `SPI_BAUDRATEPRESCALER_64` → делитель 64 → **SCK = 96 МГц / 64 = 1.5 МГц** (≤ 3 МГц,
  с запасом на длинный жгут переходной платы). Прескейлер 32 дал бы ровно 3.0 МГц — на границе,
  не берём.
- Реализация: в `Lab_Init` переинициализируем **только экземпляр `hspi4`**
  (`hspi4.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_64; HAL_SPI_Init(&hspi4)`); `.ioc` и
  `MX_SPI4_Init` не трогаем (тот же приём, что `pintest` в LAB05 применяет к UART).
- Команда `spistat` печатает частоту, **вычисленную** из `HAL_RCC_GetPCLK2Freq()` и делителя из
  `BaudRatePrescaler`, а не константой.

## 5. Источник длительностей сброса и ожидания

Владелец добавил даташиты в `docs/reference/` (в `.gitignore`, в репо не идут): **DWM1000 Data
Sheet v1.8** (модуль) и DW1000 User Manual v2.17 (чип). Числа теперь из документов:
- **минимум импульса RSTn (низкий уровень) = 10 нс** — DWM1000 DS §1.2 «DWM1000 Power Up»
  (стр.5): *«An external circuit can reset the DWM1000 by asserting RSTn for a minimum of 10 ns…
  RSTn should never be driven high by an external source.»* Держим `DW_RST_LOW_MS = 2` мс
  (HAL_Delay работает в мс; 2 мс ≫ 10 нс — запас на дребезг/шум жгута);
- **ожидание после отпускания RSTn** — модуль входит в INIT ~за 4 мс, INIT→IDLE +5 мкс
  (UM Table 1, стр.14-15). Берём `DW_RST_WAIT_MS = 5` мс (> 4 мс). Дополнительно DS Table 1
  «Power-up Timings»: TEXT_ON = 3 мс, TDIG_ON = 3 мс (RSTn удерживается низким внутренней
  схемой ~3 мс при подаче питания);
- требование «открытый сток, высоким уровнем извне не подавать» — DS §1.2 (дословно выше) +
  Table 3 «RSTn … Active Low Output. May be pulled low by external open drain driver»; физически
  соблюдено (PE10 = OD, запись 1 → высокоимпеданс).

Прочие факты (подтверждены дословно, DW1000 UM): `DEV_ID = 0xDECA0130` (§7.2.2, стр.64; в
даташите модуля DEV_ID не приводится); порядок байт на шине младшим вперёд → `30 01 CA DE`
(Figure 3, стр.11); зарезервированные регистры → `0xDEADDEAD` (§7.2); заголовок чтения
одиночного регистра = `0x00` (§2.2.1.2). Из DWM1000 DS: **режим CPOL=0/CPHA=0 (Mode 0)**
подтверждён Figure 2 (стр.6, SPIPOL=0/SPIPHA=0); MSB first (§1.3); SPICLK ≤ 3 МГц пока CLKPLL
не залочен, до 20 МГц в IDLE (Table 2).

Прочие факты (подтверждены дословно, DW1000 UM): `DEV_ID = 0xDECA0130` (§7.2.2); порядок байт
на шине младшим вперёд → `30 01 CA DE` (§2.2.1.2, Figure 3); зарезервированные регистры →
`0xDEADDEAD` (§7.2); заголовок чтения одиночного регистра: бит7=0 (read), бит6=0 (без
суб-адреса), адрес в младших 6 битах, для DEV_ID = `0x00` (§2.2.1.2, Figure 2); MSB first; CSn
низкий всю транзакцию.

## 6. Команды работы

Консоль по USB CDC (как в LAB03–LAB08), встроенная `help`. Набор минимальный:
- `devid` — читает регистр `0x00`, печатает сырые 4 байта в порядке приёма, собранное
  32-битное значение и вердикт: совпадение с `0xDECA0130`, `0xDEADDEAD` (SPI жив, но адрес
  не тот), all-zeros (нет MISO), all-ones (MISO завис в 1), иначе — «мусор»;
- `dwreset` — повторить аппаратный сброс модуля по RSTn;
- `spistat` — фактическая частота SCK и режим CPOL/CPHA.

Вывод — только ASCII/английский (§4 п.7 хэндоффа). Копирайт в шапке файла — по §4 п.6.

## 8. Что осталось неясным / разошлось с ожиданиями

1. **Datasheet — предоставлен, пункт закрыт.** Изначально в репозитории были только User
   Manuals; владелец добавил **DWM1000 Data Sheet v1.8** (+ DW1000 UM) в `docs/reference/`.
   По нему уточнены источники (§5): минимум импульса RSTn = **10 нс** (DS §1.2), режим **Mode 0**
   (DS Figure 2), потолок SPI ≤3 МГц в INIT / 20 МГц в IDLE (DS Table 2). Наши консервативные
   `#define` (low 2 мс, wait 5 мс) остаются — они с запасом над паспортными минимумами.
   Отдельного **DW1000 Datasheet чипа** (с таблицей GPIO5/6→SPI Mode) в наборе всё же нет —
   но численный режим Mode 0 подтверждён даташитом модуля, поэтому это не блокер.
2. **GPIO vs PINOUT-предложение.** PE9 сделан `INPUT` (в PINOUT предлагался `EXTI9`), PE10
   стартует в LOW (в PINOUT предлагался HIGH). По тексту задачи оба выполнены; для devid
   безвредны. Если владелец хотел EXTI9 / стартовый HIGH — это правка `.ioc` на его стороне
   (мы `.ioc` не трогаем); для речевого этапа LAB09 (IRQ по приёму) EXTI9 вероятно понадобится.
3. **Инерция от копии LAB08.** Блок LAB09 в `.cproject` унаследовал от LAB08 линковку
   `libcodec2_cm4.a` и `libPDMFilter…` — для devid не используются, безвредны (линковка
   прошла). При желании их можно убрать из конфигурации LAB09 отдельно.
4. **SCK 1.5 МГц** выбран консервативно (≤ 3 МГц с запасом на жгут); при надёжном монтаже на
   коротком жгуте можно поднять до 3 МГц (INIT) и до 20 МГц после выхода в IDLE — это предмет
   следующих шагов LAB09.

## Порядок проверки на железе (владелец)

Прошить LAB09 на кит с подключённым модулем, открыть консоль (COM-порт), выполнить `devid` —
ожидается `0xDECA0130`. Повторить на втором ките со вторым модулем (обе переходные платы).
`spistat` покажет фактическую SCK и режим; `dwreset` — повторный сброс при необходимости.
