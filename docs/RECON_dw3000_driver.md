Автор: Vagan Sarukhanov · Дата: 2026-08-28 · Ветка `main` · Коммит `98a1708`

Разведка перед радиоэтапом LAB09: чем брать драйвер DW3000 для STM32F411 (без RTOS, главный
цикл, HAL SPI). **Кода не писали, драйвер не переносили** — решение о переносе принимает владелец
после чтения. Ниже — только факты со ссылками; правовых оценок не выносим (никто из нас не юрист).
Напоминание владельца остаётся в силе: лицензионно чистых путей два — соблюдать условия Qorvo как
они есть, либо написать свой код по документации на регистры, не заглядывая в их исходники;
«глубокий рефакторинг чужих исходников» лицензионных обязательств не снимает.

## ФАКТЫ Б — объём и пригодность открытого драйвера

- **Б1. Размер (04.00.00, `zephyr/decadriver`)** — 6 файлов: `deca_device.c` (~201 КБ, весь код
  драйвера, ≈5–6 тыс. строк — оценка по размеру), `deca_device_api.h` (~115 КБ), `deca_regs.h`
  (~155 КБ, регистры), `deca_types.h`, `deca_vals.h`, `deca_version.h`. (`deca_params_init.c` в
  04.00.00 отсутствует — вся логика в `deca_device.c`.) Новый `dwt_uwb_driver` 08.02.02 крупнее и
  разбит: `dw3000_device.c` (390 КБ), `dw3720_device.c` (442 КБ), `deca_compat.c` (149 КБ), ~35 файлов.
- **Б2. Платформенная привязка.** `decadriver/` target-independent; порт-слой изолирован в
  `platform/` (SPI/GPIO/задержки). Для F411+SPI4 менять надо **только platform-слой** (SPI-транзакции,
  GPIO CS/RST/IRQ, задержки), сам драйвер не трогать. ⚠️ Готового STM32 HAL platform-слоя нет — у br101
  есть только `zephyr/esp-idf/nrf-sdk` (`dw3000_spi.c`, `dw3000_hw.c`), под STM32 писать самим.
  Ожидание задачи «заменяется тонкий слой SPI/GPIO» — **подтверждается**.
- **Б3. Окружение.** Сам decadriver RTOS не требует (взаимодействие с платформой через SPI/GPIO-колбэки);
  RTOS навязывают порт-репозитории (foldedtoad — Zephyr 3.6; br101 — Zephyr/ESP-IDF/nRF SDK). Про
  обязательный `malloc` и конкретные версии STM32 HAL — **не найдено**. Наше требование (без RTOS,
  главный цикл) с самим драйвером совместимо, но с готовыми портами — нет (их порт-слой под RTOS).
- **Б4. Flash/RAM.** Числовых значений нигде не приводится (README foldedtoad: «not specified») —
  **не найдено**. Косвенно: бинарник собран `-m4-hfp`, MAC-стек отдельной `.a`. Запас у нас есть
  (сейчас LAB09 ~49 КБ flash из 512, ~13 КБ RAM из 128), но точную цифру драйвера дать нельзя.

## ФАКТЫ В — свой драйвер по документации (DW3000 User Manual v1.1)

⚠️ Единой нумерованной «прошейте регистры в этом порядке» последовательности UM **не даёт** — она
вынесена в API `dwt_initialise()/dwt_configure()` [3]. Ниже — минимум, собранный из явных утверждений UM.

**В1. Минимальная последовательность (передать и принять один кадр):**
1. Аппаратный сброс по RSTn → чип сам INIT_RC→IDLE_RC; в INIT_RC SPI ≤ 7 МГц (UM §2.5 Figure 8, §2.4 Table 4).
2. Дождаться готовности SPI (host-interrupt/SPIRDY после ~70 мкс OTP-boot) (UM §2.5.1.2).
3. **OTP-«kick» калибровок** через `OTP_CFG (0x0B:08)`: XTAL_TRIM, LDO_KICK, BIAS_KICK, DGC_KICK
   (UM §7.3 Table 17, §8.2.12.3).
4. **PLL:** `PLL_CFG (0x09:00)` по каналу (Table 35: 0x1F3C ch5 / 0x0F3C ch9), `PLL_CAL (0x09:08)`
   =0x81+CAL_EN (UM §8.2.10).
5. **Выход в IDLE_PLL:** бит `AINIT2IDLE` в SEQ_CTRL → ждать `CPLOCK` в `SYS_STATUS (0x00:44)`; после
   лока SPI можно до 38 МГц (UM §2.5, §2.4).
6. **Конфиг канала/скорости/преамбулы:** `CHAN_CTRL (0x01:08)` (канал + TX_PCODE, код задаёт PRF),
   `TX_FCTRL (0x00:18/24)` (преамбула, data rate, длина) (UM §3.1, §8.1 Table 19).
7. **TX:** записать кадр в `TX_BUFFER (0x14)` → fast-command **CMD_TX (0x1)** → ждать `TXFRS` в
   SYS_STATUS, снять W1C; FCS чип добавляет сам (UM §3.1 Figure 14, §9 Table 46).
8. **RX:** одноразовая PGF-калибровка `RX_CAL (0x04:0C)` (CAL_MODE=1, проверить RESI/RESQ) →
   fast-command **CMD_RX (0x2)** → ждать `RXFCG` (валидный CRC) → длину из `RX_FINFO (0x00:4C)` RXFLEN
   → читать `RX_BUFFER_0 (0x12)` → снять статус (W1C или CMD_CLR_IRQS) (UM §4.1, §8.2.5, §9).

**В2. Сложнее, чем DW1000** (UM §2.2: *«modified software is needed since the DW3000 control register
interface is different to that of the DW1000»*): иной формат SPI-заголовка + fast-command + masked
write; явная машина состояний с ожиданием `CPLOCK` и переклокингом SPI (7→38 МГц); обязательные
OTP-kick загрузки; обязательные PLL- и RX(PGF)-калибровки (для ch9 — переколибровка при ±20 °C).
Заявленное «simplified interface» относится к прикладному API, не к этим низкоуровневым шагам.

**В3. Переиспользуется из `uwb_core.c` / добавить:**
- *Переиспользуется:* механика SPI-чтения (`uwb_cs_low/high`, CSn на всю транзакцию, Transmit+Receive),
  `uwb_read_reg` и адаптерный `UwbChip_BuildReadHeader` (короткий 1-октетный read), аппаратный сброс
  `uwb_hard_reset`, каркас консоли/команд, `uwb_sck_hz`/переклок `hspi4`, чтение и верификация DEV_ID.
- *Добавить:* **запись регистра** + 1-октетный write-заголовок и **2-октетный full-address заголовок
  с 7-битным sub-address** (почти вся конфигурация адресуется суб-адресом); **fast-command** транзакция
  (CMD_TX/CMD_RX/CMD_TXRXOFF/CMD_CLR_IRQS); опц. **masked write** (AND/OR); запись `TX_BUFFER`/чтение
  `RX_BUFFER_0` со смещением; **bring-up в IDLE_PLL** (AINIT2IDLE + опрос CPLOCK); **OTP read+kicks**;
  конфиг канала (TX_FCTRL/CHAN_CTRL/PLL_CFG/PLL_CAL, antenna delay); **RX PGF-калибровка**; обработка
  `SYS_STATUS` (TXFRS/RXFCG + ошибки, W1C), опц. линия IRQ + `SYS_ENABLE`.

## ЧТО ЭТО МЕНЯЕТ (для решения владельца)

- Готовых **лицензионно-нейтральных** исходников DW3000 под STM32 нет: открытый 04.00.00 — файлы
  Decawave «All rights reserved» (permissive-гранта нет), новый 08.02.02 — Qorvo license с
  ограничением «только с чипами Qorvo» и запретом реверса, 06.00.14 — бинарь без исходников и не под наш МК.
- Оба «чистых» пути реальны: (а) взять драйвер Qorvo и соблюдать его условия как есть (мы используем
  именно чип Qorvo, так что аппаратное ограничение выполняется само собой), написав только platform-слой
  под F411/SPI4; (б) написать свой тонкий драйвер по регистрам (В1), не заглядывая в их исходники.
- Свой путь по объёму: наш каркас (`uwb_core.c`) переиспользуется; добавить запись/суб-адрес/fast-cmd
  + bring-up IDLE_PLL + OTP-kick + PLL/RX-калибровки — заметно больше, чем было для DW1000, но обозримо.
- **Драйвер не переносим и в дерево не кладём** — выбор пути за владельцем.
