# TASK: LAB09 шаг 2 — разведение путей DW1000 / DW3000

Автор: Vagan Sarukhanov
Дата: 2026-08-27

## Что уже подтверждено железом

Существующая прошивка LAB09, написанная под DW1000, **без единой правки прочитала
идентификатор DWM3000 на обеих сборках**:

```
devid raw (bus order, low octet first): 02 03 CA DE
devid = 0xDECA0302  (expected 0xDECA0130)
verdict: unexpected value - garbage (check wiring, SCK<=3MHz, SPI mode 0)
```

Совпадение не случайное: заголовок чтения регистра с адресом 0 у обоих поколений
укладывается в один октет `0x00` (при разной логике полей), порядок байт данных в обоих
случаях младшим вперёд, режим SPI 0 и скорость 1.5 МГц подходят обоим.

Тем самым проверены и **не подлежат пересмотру**: монтаж жгута, питание с Arduino-разъёма
при J1 в верхнем положении, режим SPI, делитель, процедура сброса, конфигурация сборки
LAB09, привязки к номеру работы и консоль. Модули — серийные DWM3000 (наклейка без
суффикса), исполнение без фазового пеленга, оба одинаковые.

Слово «garbage» в выводе — дефект вердикта, а не железа: команда сравнивает только с
идентификатором DW1000.

## Решение владельца по архитектуре

**LAB09 остаётся ОДНОЙ работой курса.** Отдельный номер работы под DW1000 не заводить —
студенту нечего показывать на железе, которого нет.

Структуру брать по образцу разделения LAB07/LAB08, но **только файловую, без второго
номера работы**:

- общая часть уезжает в `App/Common` — сброс модуля, каркас консольных команд, транзакция
  чтения регистра по SPI, разбор и печать ответа, диагностика по характеру ответа;
- над ней **два тонких адаптера**, различающиеся сборкой заголовка транзакции и ожидаемым
  идентификатором;
- выбор чипа — **флагом сборки, по умолчанию DW3000**;
- путь DW1000 сохраняется целиком и включается одной строкой, когда приедут новые модули.

Имена файлов и флага предложить, окончательные — за владельцем. Флаг размещать по образцу
того, как это сделано в соседнем проекте `mks-firmware` (отдельный заголовок конфигурации
платы, значение по умолчанию задано явно), а не россыпью по коду.

## Работа

### 1. Вынести общее в `App/Common`

Из нынешнего `App/Labs/uwb_link.c` выделить то, что не зависит от поколения чипа. Границу
проводить по факту, а не по предположению: посмотреть, что реально общее, и это перечислить
в отчёте. Ожидание — сброс, каркас команд, обмен по SPI, печать; проверить.

### 2. Два адаптера

Каждый отвечает минимум за: построение заголовка чтения регистра, ожидаемое значение
идентификатора, толкование ответа. Формат заголовка DW3000 брать из `docs/RECON_dw3000.md`
и перепроверять по DW3000 User Manual в `docs/reference` — не по памяти и не по аналогии
с DW1000.

### 3. Исправить вердикт `devid`

Сейчас вердикт жёстко привязан к DW1000. Требуется:

- сравнивать с идентификатором того семейства, под которое собрана прошивка;
- **у DW3000 считать корректными оба значения** — и без фазового пеленга, и с ним:
  документы не позволяют однозначно привязать DW3110 к одному из них, поэтому оба валидны,
  и печатать, какое именно исполнение обнаружено;
- сохранить существующие ветки диагностики: все нули, все единицы, значение-маркер
  несуществующего регистра, иное;
- в выводе печатать, под какое семейство собрана прошивка — иначе при переключении флага
  результат нечитаем.

### 4. Команда `spistat`

Дополнить сведениями, актуальными для собранного семейства: потолок частоты SPI в текущем
состоянии устройства. У DW3000 он иной, чем у DW1000, — значение брать из документов.

### 5. Сборка и коммит

Собрать LAB09 **в обеих конфигурациях флага** — с DW3000 и с DW1000 — до чистой сборки
(0 ошибок, 0 предупреждений). Это главная проверка того, что разведение не сломало
сохраняемый путь. Затем commit + push, хеш в отчёт.

## Чего НЕ делать на этом шаге

- Не переносить драйвер Qorvo и не начинать радиообмен — это следующий шаг, решение о
  драйвере принимает владелец отдельно.
- Не трогать `walkie-talkie.ioc`, HAL, CMSIS, `Drivers/BSP`, `ThirdParty` (§4 п.2 хэндоффа).
- Не менять раскладку выводов — она проверена железом.

## Что сдать

Отчёт `docs/REPORT_lab09_split.md`:

1. Где прошла граница между общей частью и адаптерами, и что оказалось общим по факту.
2. Имена файлов и флага, значение по умолчанию, где флаг объявлен.
3. Как устроен вердикт `devid` теперь, полный список веток диагностики.
4. Результат сборки в обеих конфигурациях флага, с размерами секций для каждой.
5. Хеш коммита.
6. Отдельным разделом — что разошлось с ожиданиями или осталось неясным.

## Проверка на железе (владелец)

Прошить LAB09 в конфигурации DW3000 на оба кита, выполнить `devid` — ожидается
`0xDECA0302` и внятный положительный вердикт вместо нынешнего «garbage». Проверить
`spistat`.
