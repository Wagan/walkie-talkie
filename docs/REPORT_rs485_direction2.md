# Отчёт: TASK_rs485_direction2 (этап 2) — управление направлением RS-485

Реализовано управление направлением полудуплекса в транспортном слое, нейтрально к физслою (эту же
точку потом займёт драйвер HC-12). По умолчанию физслой **TTL** — DE не трогается, поведение прежних
работ (LAB02–05) и LAB04 не меняется. Не трогались: `.ioc`, HAL, BSP, ThirdParty, приоритеты NVIC,
кодеки, кадрирование, джиттер-буфер, prefill, probe A/B/C, LAB04. Сборка **всех шести конфигураций
(LAB00/02/03/04/05/07) — 0 ошибок, 0 предупреждений**. Прошивка и проверки на железе — за владельцем.

Вывод направления — **`RS485_DE` (PE7)**, DE и /RE связаны (решение 5): HIGH = передача, LOW = приём.
Базис владельца (PE7 в CubeMX) — коммит `5ca0e19`; init-уровень по сбросу LOW (приём).

## Как работает секвенс направления

1. **Подъём — до первого байта, в контексте потока** (старт отправки): `rs485_dir_tx_begin(nbytes)`
   выдерживает защитный интервал `pre` (мкс, по умолч. 0), поднимает DE, запоминает `DWT` и считает
   **дедлайн сторожа** = время кадра (`nbytes × 10 бит / baud`, 8N1) + `post` + запас сторожа.
2. **Опускание — строго по TC**: `HAL_UART_TxCpltCallback` вызывается HAL по флагу **TC** (последний
   стоп-бит ушёл из сдвигового регистра — установлено разведкой 1.3, не по опустошению DR и не по
   DMA). Там `rs485_dir_rx(1)` выдерживает `post` (мкс, умолч. 0) и опускает DE. **Никогда по
   освобождению регистра.**
3. **Блокирующий `sendbyte`**: `HAL_UART_Transmit` возвращается только после `UART_FLAG_TC` (разведка
   1.3), поэтому подъём — до вызова, опускание (`rs485_dir_rx`) — после возврата = после фактического
   TC, а не «после возврата из функции» в смысле раньше времени.
4. **Опускание по ошибке**: если передача не стартовала (`HAL_..._Transmit_IT != HAL_OK`) или
   блокирующая вернула не HAL_OK, либо сработал `HAL_UART_ErrorCallback` — `rs485_dir_error()` вернёт
   DE в приём и сосчитает `err_drops`. Иначе шина осталась бы занята навсегда (аналог застрявшего
   радиопередатчика) и сосед бы оглох.
5. **Сторожевой таймер**: `UartPort_Rs485Poll()` (зовётся из `Lab_Process` LAB07) — если DE поднят
   дольше дедлайна (время кадра + запас), принудительно опускает, освобождает `txBusy` и считает
   `wd_trips`. Короткая критическая секция (`__disable_irq`) — чтобы не разъехаться с опусканием по TC
   из ISR. Запас — параметр `rs485 wd <marginUs>` (умолч. 3000 мкс).

**Защитные интервалы — параметры в мкс, не константы** (`rs485 guard <preUs> <postUs>`): по разведке
1.5 минимальное удержание после последнего байта = 1041.7 мкс на 9600 … 10.85 мкс на 921600 —
значения считаются от baud автоматически (в дедлайне сторожа), а `pre`/`post` добавляют запас поверх.
Этот же механизм обслужит время разворота HC-12.

## Счётчики (команда `rs485`, сброс — `reset`)

- `turnaround last/max` — измеренное время удержания DE (по DWT), мкс. Ожидание на 460800 для кадра
  речи ~13 Б ≈ ~280 мкс + `pre`/`post`.
- `premature` — опусканий DE **до** TC. Самопроверка: `rs485_dir_rx` штатного пути сверяет флаг TC;
  должно быть **0** (критерий приёмки 2).
- `wd_trips` — срабатываний сторожа (зависшая передача). В норме 0.
- `err_drops` — опусканий по ошибке передачи. В норме 0.

## Выбор физслоя командой (по образцу `decim`)

`phy ttl|rs485` на живой плате (LAB07 и LAB03), без перепрошивки. Смена слоя только ставит флаг и
опускает DE в приём — **звук не рвётся** (буферы/джиттер не трогаются). Для RS-485 печатается пометка
про полудуплекс.

## Полудуплекс и нагрузочные тесты (решение 4)

RS-485 — полудуплекс: встречная одновременная передача невозможна (драйверы столкнутся).
`UartPort_PhyAllowsContention()` = 0 при RS-485. **LAB03 `flood`** (главный нагрузочный опыт со
встречной передачей) при `phy rs485` **внятно отказывает** («not applicable on RS-485 (half-duplex)…
Use 'phy ttl'»), а не роняет/вешает линию. **LAB02** нагрузочный режим (`LAB02_MODE=LOAD`) —
компилируемый, консоли и команды `phy` у LAB02 нет, поэтому выбрать RS-485 там нельзя: LAB02 всегда
идёт по TTL, столкновения не возникает по построению (в докладе фиксируется как ожидаемое). LAB07 —
PTT-полудуплекс, говорит один, RS-485 штатен.

## Безопасность старта (дополнение к монтажу)

Init-уровень PE7 по сбросу — LOW (приём): плата стартует слушателем, шину не занимает. Владельцем
добавляется внешняя подтяжка PE7 к земле ~10 кОм (в третьем состоянии до инициализации вход DE
определён как приём) — это на прошивку не влияет, отмечено для монтажа.

## Порядок проверки (владелец, две платы, критерии приёмки)

Монтаж: A, B и сигнальная земля; терминаторы 120 Ом на концах; смещение 560–680 Ом (A к питанию, B к
земле); подтяжка PE7 к земле 10 кОм; экран с одного конца. RO→PA3 напрямую (PA3 FT, делитель не нужен).

1. На обеих платах `phy rs485`. Прогнать лесенку: `codec raw`+`rate 16000`+`baud 921600`, затем
   `ulaw`, `adpcm`, `codec codec2` во всех `c2mode` — речь идёт как по TTL (критерий 1).
2. `rs485`: `premature=0` на всех скоростях (критерий 2), `turnaround max` разумный (≈ время кадра +
   guard). `voice`: `probeA over=0`, `qover=0`, `ring_over=0`, `under=0`, `lost=0` (критерий 3).
3. Переключать `phy ttl`↔`phy rs485` во время разговора — звук не рвётся (критерий 4).
4. Пауза при обоих опущенных драйверах — приёмник молчит (смещение линии; критерий 5).
5. Сброс одной платы — вторая продолжает принимать, шина не занимается при старте (критерий 6;
   обеспечено init-уровнем LOW + внешней подтяжкой).
6. При росте `wd_trips`/`err_drops` (не должно быть) — смотреть линию/тайминги; `rs485 guard`/`wd`
   для настройки запасов под конкретный кабель (12.5 м).

аварийное опускание и сторожевой таймер, защитные интервалы-параметры в мкс, выбор физслоя командой,
счётчики (разворот, premature, wd, ошибки). Прежние работы и LAB04 не затронуты (умолчание TTL).
