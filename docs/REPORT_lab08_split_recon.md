# Отчёт (разведка, без правок кода): разделение LAB07 (сжатие) и LAB08 (радио)

Тип — разведка. Код не менялся. Факты — по исходникам (файл:строка). Границу разделения выбирает
владелец по этому отчёту. В конце — решения владельцу.

> **Ключевой вывод сразу.** `speech.c` (1339 строк) — это на **~75–80 % общий голосовой движок**
> (захват→кодек→кадр→UART→джиттер→декод→воспроизведение), одинаковый для провода и радио. **Радио
> (HC-12) использует ТОТ ЖЕ транспорт** — модуль по UART на PA2/PA3 (USART2), поэтому транспорт **не
> раздваивается**: разница провод↔радио на уровне кода тонкая — это **умолчания** (field default
> 9600/Codec2/8к vs провод) и **подмножество команд** (сравнение/замер = LAB07; поле/канал = LAB08).
> Поэтому честное разделение — не «разрезать пополам», а **вынести общий движок в `App/Common` и
> оставить в работах тонкие адаптеры** (свои умолчания + свой набор команд). Лёгкий вариант «одна
> прошивка, разные умолчания» владельцем отвергнут — здесь предлагается именно вынос движка.

## 3. Конфигурация работ

- **Выбор работы — символ `LAB_ID`** (`App/Common/Inc/lab.h`): guard-список реализованных
  `(0,2,3,4,5,7)` (`lab.h`, `#elif (LAB_ID != 0) && …`). Каждый файл работы обёрнут `#if LAB_ID==<n>`
  и реализует `Lab_Init`/`Lab_Process`. **Для LAB08:** дописать `(LAB_ID==8)` в guard `lab.h` (одна
  строка) и завести `App/Labs/<radio>.c` под `#if LAB_ID==8`.
- **Конфигурации сборки — вручную в `.cproject`** (чувствительный файл; в `.gitignore` есть
  `.cproject.bak.before-*`). Сейчас 6 блоков `cconfiguration` (name="LAB00".."LAB07", у каждого свой
  `LAB_ID=n` и `buildPath`). **Для LAB08 нужен новый блок** = копия блока LAB07 (в нём уже подключены
  `-I ThirdParty/codec2/src` и `-l:libcodec2_cm4.a`, нужные Codec2) с **регенерацией id**, `LAB_ID=8`,
  `buildPath=LAB08`. **Без правки `.cproject` не обойтись** — либо ручная копия блока (как делали для
  LAB00/02, см. хендофф §5), либо через IDE (Build Configurations → New → copy of LAB07 → задать
  `LAB_ID=8`). Затронутые файлы: только `.cproject` (+ каталог сборки `LAB08/` в `.gitignore`).
  ⚠️ **Codec2-линковка есть ТОЛЬКО в конфигурации LAB07** — новый LAB08 должен её повторить, иначе
  undefined reference на `codec2_*`.
- **Реестр команд — ПО-РАБОТНЫЙ** (`Console_Register(cmds, count)`, `console.h:58`): каждая работа
  регистрирует **свой** массив `k_cmds[]`. Значит **у LAB07 и LAB08 могут быть разные наборы команд**
  без конфликтов — это прямо поддерживает разделение (LAB07: `decim/load/budget/c2load/headroom`;
  LAB08: `phy/prefill/…`; общие базовые — в обоих).

## 4. Предлагаемая раскладка после разделения

**Идея: вынести общий голосовой движок в `App/Common/voice.{h,c}` (guard `#if (LAB_ID==7)||(8)`),
работы — тонкие адаптеры.**

| Единица | Откуда | Куда | Объём |
|---|---|---|---|

| Джиттер-буфер (`jb_*`, состояние, prefill-переменная) | `speech.c:138–206,441–468` | `voice.c` | ~90 стр |
| Codec2-интеграция (таблица, экземпляр, кольцо, `c2_get`, `c2_tx_process`, декод в `voice_sink`) | `speech.c:228–344,486–638` | `voice.c` | ~300 стр |
| Кадровый обмен (offload-очередь, `frame_enqueue`, `voice_rx_byte`, `tx_flush`) | `speech.c:159–180,345–409,473–485` | `voice.c` | ~120 стр |
| Счётчики + probe C (loop_max) | `speech.c:151–158,…` | `voice.c` | ~40 стр |

| **Новое LAB08 `App/Labs/radio_voice.c`:** field-умолчания (Codec2/8к/9600), команды `phy`/`prefill`/бюджет-в-поле/потери + `Lab_Init` LAB08 | — | новый | ~150 стр |

**Неочевидные места (нужны обеим, но по-разному) и как разрешить:**
1. **Умолчания** (codec/rate/baud/prefill/headroom): движок хранит переменные, но **начальные
   значения задаёт работа** через `Voice_Config`-структуру или отдельную `Voice_SetDefaults(...)` из
   `Lab_Init`. Цена — маленькая (одна структура/функция). LAB07: провод (напр. 460800, лесенка);
   LAB08: field (Codec2/8к/9600, prefill 60).
2. **`decim fir|avg`**: FIR-децимация общая, режим `avg` — только сравнение (LAB07). Резолюция:
   метод децимации — переменная в движке (по умолч. FIR), команда `decim` регистрируется **только в
   LAB07**. LAB08 всегда FIR. Цена — нулевая.
3. **`budget`**: таблица канала полезна обоим (LAB07 — как расчёт, LAB08 — на практике). Резолюция:
   функция печати бюджета — в движке/общей, команда регистрируется в обеих (или в LAB08 расширенная).
4. **`load`/`c2load`/`DWT-замер`**: цена сжатия — обучение LAB07; но `c2Enc/Dec` живой замер нужен и
   в `voice` (обе). Резолюция: счётчики живого замера — в движке; команды `load/c2load` — только LAB07.
5. **`phy`/`rs485`**: HC-12 = `phy ttl` (нет DE, `REPORT_hc12_recon.md` §11). RS-485 — отладочный
   стенд направления. Резолюция: механизм направления уже в `uart_port.c` (Common), команды
   `phy/rs485` — в LAB08 (и/или LAB07 для стенда RS-485). Цена — нулевая (уже вынесено).

## 5. Риски регресса (что может сломаться и как проверить)

1. **Вытеснение/приоритеты** — `Preempt_AudioOutHighest()` зовётся из `Lab_Init` работы **и после
   смены baud** (`speech.c:1241` баланс с `UartPort_SetBaud`). LAB08-адаптер **обязан** повторить это
   в своём `Lab_Init`; иначе вернётся дефект коротких провалов звука. `preempt.c` guard → +8.
   **Проверка:** `voice` → `probeA over=0` за 5+ мин на LAB08.
2. **DWT** — включается в `uart_port.c UartPort_Init` (без сброса) и в `speech.c Lab_Init`. Движок/
   LAB08 должны гарантировать `CYCCNT` включён до замеров (loop_max/turnaround/headroom-us).
   **Проверка:** ненулевые разумные `loop_max`/`turnaround` в `voice`.
3. **probe A/B/C** — A в `audio.c` (guard +8), B в `uart_port.c` (guard +8), C (loop_max) переезжает
   в движок. Счётчики и их сброс (`reset`) не потерять при переносе. **Проверка:** все три probe
   печатаются и обнуляются в LAB08.
4. **prefill/ёмкость JB** — `JB_SIZE=4096` (256 мс), `g_jbPrefill` (60 мс) переезжают в движок; лимит
   `prefill` = половина ёмкости. Не «уменьшать prefill без спроса». **Проверка:** `under=0`,
   `over=0` на радио, `prefill/cap` в `voice`.
5. **Грабля `baud` из `.ioc`** — field default обходит её `UartPort_SetBaud(9600)` в `Lab_Init`
   (`speech.c:1241`). LAB08 обязан сохранить это; LAB07 (провод) может иметь ДРУГОЙ дефолт скорости —
   не потерять при разнесении умолчаний. **Проверка:** после прошивки LAB08 стартует на 9600 без
   команд (критерий field default).
6. **LAB04 и прочие** — вынос движка из `speech.c` их не трогает (LAB04 — свой `voice_wire.c`);
   единственное касание Common — **аддитивное** добавление `(LAB_ID==8)` в guard-условия. **Проверка:**
   пересобрать LAB00/02/03/04/05 — 0/0, поведение не изменилось; guard-правки не трогают их код.
7. **Codec2-линковка** нового LAB08-конфига (иначе undefined reference). **Проверка:** LAB08 линкуется.
8. **Реестр команд** — при разнесении не потерять базовые команды у обеих работ и не задвоить.
   **Проверка:** `help` в LAB07 и LAB08 показывает ожидаемые наборы.

## 6. План этапов (после каждого — сборка и проверка на железе)

- **Этап 0 — инфраструктура LAB08 (без переноса логики).** `.cproject`: новый блок LAB08 (копия
  LAB07, `LAB_ID=8`, Codec2-линковка); `lab.h` guard +8; временный `App/Labs/radio_voice.c` под
  `#if LAB_ID==8`, который пока **дублирует поведение LAB07** (или тонко переиспользует текущий код).
  Guard `+8` в нужных Common-модулях. **Проверка железо:** LAB08 прошивается и работает как LAB07
  (речь по радио идёт, как сейчас). Все шесть собираются 0/0.
- **Этап 1 — вынос движка в `App/Common/voice.{h,c}`, LAB07 = адаптер поверх него.** Механический
  перенос общих групп (§4), `speech.c` худеет до команд сжатия + провод-умолчаний. Поведение LAB07
  **не меняется**. **Проверка железо (регресс):** LAB07 на проводе — лесенка кодеков, `decim`,
  `headroom`, `load`, `budget`, `probeA over=0`, Codec2 идёт; сравнить с текущим.
- **Этап 2 — LAB08-адаптер на движке.** `radio_voice.c` получает field-умолчания + радио-команды
  (`phy`/`prefill`/бюджет-в-поле/статистика потерь); дубль этапа 0 убирается. **Проверка железо:**
  LAB08 автономный старт (без консоли) — питание→PTT→речь на 50 м; `under/over/qover=0`.
- **Этап 3 — чистка LAB07.** Убрать из LAB07 радио-специфику (field baud/phy, если решено), финализ.
  наборы команд. **Проверка железо:** и LAB07 (провод), и LAB08 (радио) работают; `help` у обеих
  корректен; LAB00/02/03/04/05 не задеты.

Каждый этап: локальная сборка всех шести 0/0 до коммита; прошивка/проверка — владелец.
