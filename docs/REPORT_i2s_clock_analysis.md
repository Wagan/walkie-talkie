# ОТЧЁТ: совместимость тактирования двух аудиотрактов на Fs = 16 кГц

Только чтение и расчёт. Цель — демо loopback: микрофон (I2S2) и кодек (I2S3) одновременно
на Fs = 16000 Гц. Источники: `Drivers/BSP/STM32F411E-Discovery/stm32f411e_discovery_audio.c`
(в проекте), `docs/REPORT_st_audio_example.md`, RM0383 Rev 4 (§20.4.4 «I2S clock generator»,
стр. 590–591; §6.3.20 «RCC_PLLI2SCFGR», стр. 133–134) из `docs/reference`.

Вход HSE = 8 МГц (`HSE_VALUE=8000000`). PLLI2S на F411 имеет **свой** входной делитель
PLLI2SM (независим от главного PLLM=4). Диапазоны (RM0383 §6.3.20): PLLI2SM 2…63,
PLLI2SN 50…432, PLLI2SR 2…7; `f(VCO)=вход·(PLLI2SN/PLLI2SM)`, `I2SCLK=f(VCO)/PLLI2SR`.

Формат данных обоих трактов — 16 бит (`I2S_DATAFORMAT_16B` в `I2S2_Init` и `I2S3_Init`).

---

## 1. Что делают ClockConfig при Fs = 16000 (факт из исходника)

`BSP_AUDIO_IN_ClockConfig` (строки 877–906): ветка `(AudioFreq & 0x7)==0` — для 16000 истинна:
- **PLLI2SM = 8, PLLI2SN = 192, PLLI2SR = 6.**
- VCO_вход = 8/8 = 1 МГц; VCO = 1·192 = 192 МГц; **I2SCLK = 192/6 = 32 МГц.**

`BSP_AUDIO_OUT_ClockConfig` (строки 493–530): использует `freqindex`. Для 16000
`freqindex = 2` (I2SFreq[2]); проверка `(freqindex & 0x7)==0` → `2 & 7 = 2 ≠ 0` → **ветка else**:
- **PLLI2SM = 8, PLLI2SN = 258, PLLI2SR = 3.**
- VCO = 1·258 = 258 МГц; **I2SCLK = 258/3 = 86 МГц.**

**Ключевое расхождение:** вход хочет I2SCLK = **32 МГц**, выход — **86 МГц**. PLLI2S на кристалле
один, поэтому две функции борются за один ресурс (см. §4).

---

## 2. Формула частоты дискретизации I2S (RM0383 §20.4.4, дословно)

> When the master clock is generated (MCKOE in the SPI_I2SPR register is set):
> `FS = I2SxCLK / [(16*2)*((2*I2SDIV)+ODD)*8)]` when the channel frame is 16-bit wide
> `FS = I2SxCLK / [(32*2)*((2*I2SDIV)+ODD)*4)]` when the channel frame is 32-bit wide
>
> When the master clock is disabled (MCKOE bit cleared):
> `FS = I2SxCLK / [(16*2)*((2*I2SDIV)+ODD))]` when the channel frame is 16-bit wide
> `FS = I2SxCLK / [(32*2)*((2*I2SDIV)+ODD))]` when the channel frame is 32-bit wide

Дополнительно (RM0383 §20.6.5, RCC_PLLI2SPR / SPI_I2SPR): бит **ODD** — «real divider value =
(I2SDIV × 2) + ODD»; значения **I2SDIV = 0 и 1 запрещены**.

Обозначим делитель `D = 2·I2SDIV + ODD`. Тогда при 16-битном кадре:
- **MCLK включён:** `FS = I2SCLK / (256·D)`  (т.к. 16·2·8 = 256);
- **MCLK выключен:** `FS = I2SCLK / (32·D)`  (т.к. 16·2 = 32).

(HAL выбирает целочисленные I2SDIV/ODD округлением идеального `D` к ближайшему целому.)

---

## 3. Требования трактов при 16 кГц и расчёт при I2SCLK = 32 МГц

- **Вход (I2S2):** master RX, `AudioFreq = 2·Fs = 32000` (`I2S2_Init` строка 1089), **MCLK выключен**
  (строка 1093). Формула MCLK-off: `FS = I2SCLK/(32·D)` → идеальный `D = I2SCLK/(32·32000)`.
- **Выход (I2S3):** master TX на кодек, **MCLK включён** (строка 684), Fs = 16000. Формула MCLK-on:
  `FS = I2SCLK/(256·D)` → идеальный `D = I2SCLK/(256·16000)`.

Расчёт **при общем I2SCLK = 32 МГц**:

| Тракт | MCLK | Целевая FS | идеальн. D | I2SDIV, ODD | Реальн. FS | Погрешность |
|---|---|---|---:|---|---:|---:|
| Вход I2S2 | off | 32000 (прогр.) | 31.25 | I2SDIV=15, ODD=1 (D=31) | 32258.06 | **+0.806 %** |
| Выход I2S3 | on | 16000 | 7.8125 | I2SDIV=4, ODD=0 (D=8) | 15625.00 | **−2.344 %** |

(Аудио-Fs входа = 32258/2 = 16129 Гц, та же погрешность +0.806 %.)

Вывод по п.3: на 32 МГц вход приемлем (+0.81 %, а для PDM-микрофона это вообще некритично),
но **выход на кодек даёт −2.34 %** (≈40 центов, слышимая расстройка) — на общем 32 МГц кодек
неприемлем. Значит «просто взять значение микрофона для обоих» нельзя.

---

## 4. Существует ли единый PLLI2S для обоих на 16 кГц

**Со штатной парой ST — нет.** Вход программирует PLLI2S на 32 МГц, выход — на 86 МГц. Так как
PLLI2S один, вторая по времени `*_ClockConfig` перепрограммирует VCO/делители PLLI2S, а делитель
I2SDIV уже проинициализированного тракта остаётся прежним → его реальная частота уезжает. Пример:
вызвать OUT_Init (PLLI2S→86 МГц, I2S3 настроен), затем IN_Init (PLLI2S→32 МГц) — кодек теперь
получает I2SCLK 32 МГц при делителе, посчитанном под 86 МГц: `FS_out = 32e6/(256·21) ≈ 5952 Гц`
(−63 %). Тракты несовместимы при стоковых функциях.

**Но единое значение существует.** Нужно одно I2SCLK, дающее малую погрешность и там, и там.

**Рекомендуемое: I2SCLK = 86 МГц (PLLI2SM = 8, PLLI2SN = 258, PLLI2SR = 3).**
Это ровно значение из OUT-ветки ST; проверяем оба тракта:

| Тракт | MCLK | идеальн. D | I2SDIV, ODD | Реальн. FS | Погрешность |
|---|---|---:|---|---:|---:|
| Вход I2S2 (прогр. 32000) | off | 83.98 | I2SDIV=42, ODD=0 (D=84) | 31994.05 | **−0.0186 %** |
| Выход I2S3 (16000) | on | 20.996 | I2SDIV=10, ODD=1 (D=21) | 15997.02 | **−0.0186 %** |

Оба тракта ≈ **−0.019 %** — с огромным запасом в пределах любой аудио-допустимости. VCO = 258 МГц
(в диапазоне 100–432), VCO_вход = 1 МГц (рекомендуемые 1–2 МГц). Валидно.

**Альтернатива с нулевой погрешностью: I2SCLK = 20.48 МГц (PLLI2SM = 5, PLLI2SN = 64, PLLI2SR = 5).**

| Тракт | MCLK | идеальн. D | I2SDIV, ODD | Реальн. FS | Погрешность |
|---|---|---:|---|---:|---:|
| Вход I2S2 (прогр. 32000) | off | 20.0 | I2SDIV=10, ODD=0 (D=20) | 32000.00 | **0.0000 %** |
| Выход I2S3 (16000) | on | 5.0 | I2SDIV=2, ODD=1 (D=5) | 16000.00 | **0.0000 %** |

Почему это работает: точный ноль возможен только при I2SCLK = 4.096 МГц·k (кратно требованию
выхода 256·16000); тогда идеальный делитель входа = I2SCLK/(32·32000) = 4·k — тоже целый. При
20.48 МГц (k=5) оба делителя целые. VCO = 1.6·64 = 102.4 МГц (≥100, валидно, но ближе к нижней
границе), PLLI2SN = 64 (≥50). Точное 32.768 МГц недостижимо: потребовало бы PLLI2SN > 432.

**Ответ:** да, единый PLLI2S существует. Практичный выбор — **86 МГц (M=8, N=258, R=3)**, обе
погрешности ≈ −0.019 %; при желании абсолютного нуля — **20.48 МГц (M=5, N=64, R=5)**, обе 0.000 %.

## 5. Куда поместить перекрытие слабых ClockConfig (без написания кода)

Обе функции `BSP_AUDIO_IN_ClockConfig` и `BSP_AUDIO_OUT_ClockConfig` объявлены `__weak` в
`stm32f411e_discovery_audio.c`. Их можно перекрыть **сильными** одноимёнными определениями, которые
обе программируют **один и тот же** PLLI2S (выбранное значение из §4) — тогда порядок вызова Init
перестаёт ломать второй тракт.

Требование: перекрытие не должно пострадать от генерации CubeMX. Предлагаемые места (код в этой
задаче не пишем):

1. **Рекомендуется:** отдельный пользовательский файл в каталоге **вне зоны CubeMX** — например
   `App/bsp_audio_clock.c` в новой папке `App/` в корне проекта, добавленной в `.cproject`
   (`<sourceEntries>`). CubeMX такие каталоги не создаёт и не вычищает, файл гарантированно
   переживёт любую генерацию. В нём — сильные `BSP_AUDIO_IN_ClockConfig` и
   `BSP_AUDIO_OUT_ClockConfig` с единым PLLI2S.
2. Допустимо: тот же файл в `Drivers/BSP/STM32F411E-Discovery/` (эта папка добавлена вручную и
   генерацией не трогается, уже в области сборки). Минус — смешение с копией BSP от ST.
3. **Не** класть в `Core/` вне блоков USER CODE и **не** в `Middlewares/` (вычищается генерацией).
   Правка самих тел `__weak` в `stm32f411e_discovery_audio.c` возможна (папка переживает генерацию),
   но нарушает принцип «BSP держим как у ST» и требует согласовать обе функции вручную —
   поэтому предпочтительнее отдельный файл-перекрытие (вариант 1).
