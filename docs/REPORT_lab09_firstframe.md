## 1. Последовательность инициализации (`uwbinit`) и проверки

Через публичный API драйвера; каждый этап печатает результат, при провале — `FAIL` с указанием этапа
(молчаливого провала нет). Порядок — из DW3000 User Manual §2.5/§4.1 (см. `RECON_dw3000.md`) и API-обёрток:

| # | Действие | API | Проверка успеха | Ссылка |
|---|---|---|---|---|
| 1 | probe (чтение DEV_ID, выбор драйвера) | `dwt_probe` | 0xDECA0302 прочитан | UM §2.3, шаг 4 |
| 2 | дождаться готовности после сброса | `dwt_checkidlerc()` в цикле | IDLE_RC за ≤10 мс, иначе timeout | UM §2.5 (INIT_RC→IDLE_RC) |
| 3 | загрузка калибровок из OTP | `dwt_initialise(DWT_DW_INIT)` | `!= DWT_ERROR` | UM §7.3 (OTP kick); здесь драйвер зовёт `setfastrate` |
| 4 | канал/PLL/PGF, выход в IDLE_PLL | `dwt_configure(&cfg)` | `== DWT_SUCCESS` (иначе PLL lock/PGF cal fail) | UM §8.2.10 (PLL), §8.2.5 (PGF) |
| 5 | приём без таймаута | `dwt_setrxtimeout(0)` | — | UM §4.1 |

Печать (пример): `uwbinit: IDLE_RC ok` → `initialise ok (OTP loaded, SPI->fast 6 MHz)` →
`configure ok (IDLE_PLL, channel/PGF)` → `DONE - chan=5 rate=850k plen=128 pac=8 code=9 (PRF64) sfd=DW8`.
Антенная задержка, временные метки, дальномер, STS — намеренно НЕ настраиваются (не нужны для сырого кадра).

## 2. Предложенные параметры канала (умолчания, обоснование)

Ориентир — **надёжность приёма на столе**, не дальность и не скорость. Обе платы стартуют одинаково.

| Параметр | Значение | Обоснование |
|---|---|---|
| Канал | **5** (6489.6 МГц) | Нижний из двух доступных (5/9) — меньше затухание, лучше проходит; общий с DW1000 (UM §1.1, Table 8) |
| Скорость | **850 кбит/с** | Из двух (850к/6.8М) — больше энергии на бит → надёжнее приём (UM §1.1) |
| Преамбула | **128 симв.** (`DWT_PLEN_128`) | Длиннее → надёжнее захват; баланс для 850к (UM §2.10) |
| PAC | **8** (`DWT_PAC8`) | Рекомендовано для преамбулы ≤128 (комментарий enum `dwt_pac_size_e`) |
| Код преамбулы | **9/9** (TX=RX) | Код 9 → PRF 64 МГц для канала 5 (UM Table 8; коды 9–12 = 64 МГц) |
| PRF | **64 МГц** | Задаётся кодом 9; выше плотность преамбулы |
| SFD | **DW 8-бит** (`sfdType=1`) | Короткий SFD, как в примерах Qorvo для DW3000; обе платы одинаково |
| PHR | **standard** (`DWT_PHRMODE_STD`) | Стандартный кадр IEEE 802.15.4 ≤127 Б; наш кадр 14 Б (UM §2.10) |
| STS / PDOA | **off** | Защищённый STS и фазовый пеленг не нужны (дальномера нет; чип non-PDoA) |
| sfdTO | **129** | preamble + 1 + SFD(8) − PAC(8) = 129 (таймаут преамбулы) |

Окончательное решение за владельцем; `uwbcfg` позволяет сменить канал/скорость на живой плате (с последующим `uwbinit`).

## 3. Команды и формат вывода

Роли — командами (одна прошивка на обе платы). Радио-команды добавлены поверх базовых (`devid`/`devidraw`/
`dwreset`/`spistat`) — объединяются в одну таблицу в `Lab_Init`. Вывод только ASCII.

- **`uwbinit`** — полная инициализация, печать результата каждого этапа (см. §1).
- **`uwbcfg`** — без аргументов печатает текущие параметры; `uwbcfg chan 5|9`, `uwbcfg rate 850|6800`
  задают (требуют `uwbinit` для применения).
- **`uwbtx [n]`** — передать n кадров (умолч. 1), содержимое `"WT" + seq + 0xA5…`; печатает
  `uwbtx: X/n confirmed (TXFRS)` — сколько передач подтвердил флаг `TXFRS`.
- **`uwbrx on|off`** — включить/выключить приём (опросом). По каждому кадру:
  `uwbrx: #<N> len=<L> seq=<S> first=<b0 b1 b2> match=yes|no`.
- **`uwbstat [reset]`** — счётчики `tx / rx / crcErr / phrErr / rxTimeout` + состояние; `reset` обнуляет.

## 4. Приём опросом; где понадобится прерывание

Приём — **опросом `SYS_STATUS` в главном цикле** (`Dw3000Port_Poll` из `Lab_Process`). Логика: если приём
включён, читаем `dwt_readsysstatuslo()`; при `RXFCG` — читаем длину (`dwt_getframelength`, минус 2 байта
FCS), тело (`dwt_readrxdata`), сверяем с образцом, чистим статус (W1C) и **перевзводим** приём
(`dwt_rxenable`); при `RXPHE/RXFCE/RXFSL` — счётчик ошибок + перевзвод; при таймаутах — счётчик.
Прерывание по IRQ (**PE9**) **не задействовано**: вывод настроен как обычный вход, EXTI в `.ioc` не
включён, а `.ioc` мы не трогаем.

**Где понадобится прерывание:** на речевом этапе (следующий шаг) кадры идут по жёсткому расписанию
(~каждые 20 мс), а опрос в главном цикле конкурирует с разбором консоли и длинными печатями — можно
опоздать к кадру и получить переполнение приёмного буфера. Тогда нужен EXTI по IRQ (PE9), который сразу
сигналит `RXFCG`, с обработкой в стиле разгрузки ISR (как в LAB04/07). Это потребует включения EXTI9 в
CubeMX владельцем и раскладки приоритетов (`preempt.c`).

## 5. Скорость SPI: достигнут ли быстрый режим

- **Инициализация — 1.5 МГц** (`/64`): годится для INIT_RC (потолок 7 МГц, DW3000 UM Table 4). На этой
  скорости идут `dwt_probe` и старт инициализации.
- **Быстрый режим впервые достигается по-настоящему** на этапе `dwt_initialise`: **сам драйвер** зовёт
  `SPI->setfastrate()` (`dwt_uwb_driver/dw3000/dw3000_device.c:9236`), то есть переключение делает он, а
  не мы. Наш `setfastrate` ставит **6 МГц** (`/16`).
- **Выбор 6 МГц (а не 12 из шага 4):** приоритет — надёжность обмена по жгуту переходной платы; 6 МГц
  заведомо ниже потолка IDLE_PLL 38 МГц и безопасно даже в INIT_RC (7 МГц), если драйвер переключит рано.
  Меняется одной строкой (`spi_fast`).
- **Проверка обмена после переключения:** `dwt_configure` (PLL/PGF) выполняется уже на 6 МГц; при
  повреждённом SPI он вернул бы ошибку — `uwbinit` это распечатает. Фактическую работу на 6 МГц
  **подтверждает владелец на железе**; при сбоях снизить `spi_fast` и зафиксировать (см. §8).

## 6. Размеры секций и результат сборки

Headless CubeIDE, обе конфигурации — **0 errors, 0 warnings**.

| Конфигурация | text | data | bss | Δtext к шагу 4 |
|---|---|---|---|---|
| LAB09 (DW3000) | **63732** | 376 | 13552 | +4176 (радио TX/RX/config) |
| LAB09_DW1000 | 49728 | 360 | 13192 | +224 (только объединение команд) |

**Изолированная стоимость DW3000-радио** (LAB09 − LAB09_DW1000) = **+14004 байт flash, +360 байт RAM** —
драйвер (init/configure/TX/RX) + наш радио-код, после `--gc-sections`. Из ~512 КБ flash / 128 КБ RAM —
с запасом. Ветвь **DW1000 драйвер и радио не тянет** (+224 B — статический массив объединённой таблицы
команд), проверено размером и тем, что `dw3000_port.c` в ней компилируется пустым по guard.

## 8. Что разошлось с ожиданиями / осталось неясным

1. **TX-мощность не настраивалась** (`dwt_configuretxrf` не вызван): конкретные `PGdly`/`power` для канала
   в DW3000 UM не приведены (они в Application Note / примерах), выдумывать не стали — использована
   мощность по умолчанию после `dwt_configure`. Для приёма на столе (расстояние в сантиметры) этого
   достаточно; если владелец не увидит приёма, добавить `dwt_configuretxrf` с паспортными значениями канала.
2. **Fast rate 6 МГц не проверен на железе** — переключение делает драйвер в `dwt_initialise`; работу
   подтверждает владелец. При SPI-сбоях снизить `spi_fast` (напр. до `/32` = 3 МГц) и зафиксировать, на
   чём ломалось.
3. **Приём опросом** достаточен для теста «десять кадров», но для речи понадобится прерывание (EXTI PE9) —
   см. §4; это правка CubeMX за владельцем.
4. **FCS**: кадр передаётся с автодобавляемым 2-байтовым FCS (длина в `dwt_writetxfctrl` = payload+2), на
   приёме длина из `dwt_getframelength` включает FCS — вычитаем 2. Предполагается, что `dwt_configure`
   оставляет автоматический FCS включённым (умолчание драйвера); проверить на железе по `match=yes`.
5. **`sfdType=DW 8-бит (1)`** — выбор из вариантов; на связь между двумя одинаковыми платами не влияет
   (обе одинаково). При желании interop со стандартным IEEE — `sfdType=0`.

## Порядок проверки на железе (владелец)

Прошить обе платы одинаково (умолчание — DW3000). На каждой `uwbinit` — все этапы `ok`. На первой
`uwbrx on`, на второй `uwbtx 10`. Ожидание: приёмник печатает десять кадров с `match=yes`, `uwbstat` —
`rx=10`, ошибок 0. Поменять роли, повторить — тракт должен работать в обе стороны.
