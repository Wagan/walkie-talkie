# Отчёт: TASK_input_headroom — измеритель уровня и регулируемая аттенюация до кодека

Добавлены измеритель уровня микрофонного PCM (пик + подход к полной шкале, ДО и ПОСЛЕ аттенюации) и
регулируемая командой аттенюация перед кодированием. Всё **LAB07-локально** (`App/Labs/speech.c`) —
общий `audio.c`, BSP, `mic_gain`, `.ioc`, HAL, ThirdParty, кодеки, кадрирование, джиттер, prefill,
приоритеты, probe A/B/C, LAB04 — **не тронуты**. Сборка LAB07 — **0 ошибок, 0 предупреждений**.
Прошивка/замер/выбор дефолта — за владельцем (я не на железе; см. «Дефолт» ниже).

## Как устроено

**Точка применения — одна:** `Audio_OnCapture` (аудио-ISR приёма с микрофона), поотсчётно, ТОЛЬКО
при передаче (`g_ptt`). Для каждого мик-отсчёта:
1. измеряется `|отсчёт|` **до** (пик `hrPeakPre`, счёт `hrClipPre` при `|x|>=HR_NEAR_FS`) — это то,
   что даёт микрофон при `mic_gain=24`;
2. применяется аттенюация `a = (s * g_hrGain) >> 8` (Q8, 256 = ×1) — **целочисленно, без деления**,
   с сохранением насыщения;
3. измеряется `|отсчёт|` **после** (`hrPeakPost`/`hrClipPost`) — это то, что реально уходит в кодек;
4. результат кладётся в накопитель `acc16`.

**Тон не аттенюируется** — он подменяет сигнал позже, в `tx_flush` (тест-сигнал контролируемой
амплитуды). Аттенюация стоит ДО децимации 16→8, поэтому снимает и клиппинг FIR, и перегрузку ADPCM
по крутизне разом. Счётчики — `volatile`, пишет только ISR (один писатель), читает `voice`, сброс —
`reset`. Значения по умолчанию действуют и для legacy-кодеков (raw/ulaw/adpcm), и для Codec2 —
запас по уровню полезен всем; поведение самих кодеков не менялось.

## Команда

- `headroom` — показать текущую аттенюацию и Q8-усиление.
- `headroom <дБ>` — задать из набора **0 / 3 / 6 / 9 / 12 дБ** (Q8: 256/181/128/91/64). `0` = без
  аттенюации (для методички — услышать перегрузку). Набор дискретный: дБ→усиление берётся из таблицы
  (без float/pow в прошивке); значения — `10^(−дБ/20)·256`, округлённые.

Строка в `voice`:
```
headroom: atten=6dB gainQ8=128 | pre peak=NNNNN nearFS=NN | post peak=MMMMM nearFS=MM (thr=32000)
```
`pre` — микрофон как есть; `post` — что уходит в кодек. `nearFS>0` = подход к полной шкале (риск
перегрузки). Меряется при удержании PTT (речь/тон в передаче).

## Дефолт (−6 дБ) — провизорный, финализирует владелец по измерителю

Задача требует выбрать дефолт **по фактическим показаниям измерителя**. Показания снимаются на
железе, а прошивает владелец — своих цифр у меня нет. Поэтому дефолт выбран **обоснованно, но
провизорно**, и рассчитан на подстройку по измерителю:

- **−6 дБ (×0.5, `gainQ8=128`).** Обоснование: (а) `mic_gain=24` дБ — высокое фиксированное усиление,
  на громкой речи PCM у полной шкалы (доказано отзывом хрипа при снижении громкости,
  `REPORT_adpcm_overload_recon.md`); (б) перегрузка ADPCM по крутизне и клиппинг бьют в верхних
  ~6 дБ диапазона, поэтому −6 дБ убирает именно проблемную зону с запасом; (в) −6 дБ = точное
  деление на 2 (Q8=128) — самая чистая целочисленная операция и удобный ориентир для методички.

**Как владельцу финализировать дефолт (процедура):**
1. `headroom 0`, `codec adpcm`, `reset`, удерживая PTT сказать **громко** обычную фразу → `voice`:
   ожидается `pre nearFS>0` и `post nearFS>0` (перегрузка на входе кодека).
2. Поднимать: `headroom 3` → `6` → `9`, каждый раз `reset` + та же громкая фраза, смотреть `voice`:
   нужно значение, при котором **`post nearFS = 0`** на громкой речи и на слух **хрип пропал**.
3. Проверить тихую речь на этом уровне — должна остаться разборчивой и не «утонуть» по громкости
   (иначе аттенюация избыточна, взять на ступень меньше).
4. Если по цифрам оптимум ≠ 6 дБ — сообщите, я поменяю дефолт (`g_hrGain`/`g_hrDb`) одной строкой.

Если −6 дБ окажется великоват для тихой речи (кто-то говорит тихо), уменьшить до `3`; если громкая
речь всё ещё цепляет полную шкалу — до `9`. Команда для этого и сделана.

## Критерий приёмки (владелец на железе)

1. Громкая речь: `pre nearFS>0` до аттенюации, `post nearFS=0` после (на дефолте) — измеритель
   показывает и вход, и то, что уходит в кодек.
2. На дефолтном уровне громкая речь через `adpcm` **не хрипит**.
3. Тихая речь остаётся разборчивой, по громкости не проваливается (аттенюация не избыточна).
4. Повтор сравнения `adpcm` против `codec2 3200` на одной умеренной громкости даёт устойчивую
   картину, не зависящую от громкости голоса.
5. `probeA over`, `qover`, `ring_over`, `under`, `lost` остаются нулевыми (тракт не задет).

## Для методички: как ставить опыт сравнения кодеков

Перегрузка на громком входе исказила первый опыт (вокодер звучал «чище» ADPCM только потому, что
нормирует уровень). Правильная постановка:

1. Выставить **умеренную громкость** и `headroom` на выбранный дефолт (запас по уровню сохранён):
   в `voice` при обычной речи `post nearFS = 0`.
2. Сначала показать перегрузку намеренно: `headroom 0`, громкая речь на `adpcm` → хрип; затем
   `headroom 6` → хрип уходит. Студент слышит причину и лечение своими ушами.
3. Только теперь сравнивать `adpcm` против `codec2 3200` при одинаковой умеренной громкости. Вывод:
   на равных условиях **ADPCM сохраняет узнаваемость/тембр лучше**, а вокодер выигрывает **в объёме
   канала** (дальнобойность), а не в качестве. Без контроля уровня сравнение недостоверно.
