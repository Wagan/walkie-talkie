## 1. Граница «общее / адаптер» (по факту)

**Общее — `App/Common/Src/uwb_core.c`** (`#if LAB_ID == 9`): всё, что не зависит от поколения чипа —
- выводы CSn (PE11) / RSTn (PE10), тайминги и процедура аппаратного сброса `uwb_hard_reset`;
- механика SPI-чтения `uwb_read_reg` (CSn низкий на всю транзакцию, заголовок + приём данных),
  сборка значения младшим октетом вперёд, расчёт SCK `uwb_sck_hz`;
- каркас консоли и команды `devid` / `dwreset` / `spistat`, диагностика по характеру ответа
  (all-zero / all-one / 0xDEADDEAD / иное), баннер, индикация;
- `Lab_Init` (в т.ч. понижение SCK до 1.5 МГц) и `Lab_Process`.

**Зависит от чипа — адаптер** (интерфейс `App/Common/Inc/uwb_chip.h`), ровно четыре функции:
- `UwbChip_BuildReadHeader()` — построение заголовка чтения регистра (формат разный у поколений);
- `UwbChip_DevIdExpected()` / `UwbChip_IsAlive()` — ожидаемый DEV_ID и его толкование (+ исполнение);
- `UwbChip_Family()` — имя семейства для печати;
- `UwbChip_SpiCeilingNote()` — потолок частоты SPI в состоянии после сброса.

**Подтверждение «тонкости» границы:** разница образов двух конфигураций — 56 байт `text` (см. §4),
то есть от поколения зависит буквально построение заголовка + пара констант/строк, как и ожидалось.
Совпало с ожиданием задачи (сброс, каркас команд, обмен по SPI, печать — общие).

## 3. Вердикт `devid` теперь

Команда читает регистр `0x00`, печатает сырые 4 байта в порядке приёма, строку
`family=<семейство> devid=0x… (expected 0x…)` (**печатается, под какое семейство собрана прошивка** —
иначе при переключении флага вывод нечитаем), затем вердикт. Сравнение — с семейством сборки через
`UwbChip_*`. Полный список веток диагностики:

| Условие | Вывод |
|---|---|
| `UwbChip_IsAlive(val)` == 1 | `verdict: OK - <family> alive[ (<исполнение>)], SPI link works.` |
| `val == 0xDEADDEAD` | `0xDEADDEAD - SPI works but address is unused/reserved` |
| `val == 0x00000000` | `all zeros - no data on MISO (check MISO/power/reset/CSn)` |
| `val == 0xFFFFFFFF` | `all ones - MISO stuck high (miswire/absent/no power)` |
| иное | `unexpected value - not the <family> id (check wiring, SCK, SPI mode 0)` |

- **DW3000:** живыми считаются **оба** значения — `0xDECA0302` (печатает `non-PDoA`) и `0xDECA0312`
  (`PDoA`); документы не привязывают DW3110 к одному из них, поэтому оба валидны, и печатается, какое
  исполнение обнаружено. Ожидаемое для печати `expected` — `0xDECA0302`.
- **DW1000:** живое — `0xDECA0130` (исполнение одно, скобка не печатается).
- Ветки all-zero / all-one / `0xDEADDEAD` сохранены (маркер `0xDEADDEAD` действителен у обоих
  поколений, DW1000 UM §7.2 / DW3000 UM §8). Прежнее ложное «garbage» на DW3000 устранено: теперь
  `0xDECA0302` даёт `verdict: OK - DW3000 alive (non-PDoA)`.

чисто).

## 6. Что разошлось с ожиданиями / осталось неясным

1. **Минимум импульса RSTn для DW3000** в доступных документах не задан (см. `RECON_dw3000.md`).
   Процедура сброса общая; держим RSTn низким 2 мс и ждём 5 мс — с запасом над POR обоих поколений
   (DW1000 INIT ~4 мс; DW3000 ~1 мс XTAL + ~70 мкс OTP). При появлении DW3000 IC Datasheet уточнить
   одной строкой в `uwb_core.c`.
2. **Заголовок чтения для регистра 0x00 совпадает у поколений** (оба дают октет `0x00`), поэтому
   именно чтение DEV_ID работало на DW3000 и «чужой» прошивкой. Тем не менее билдер заголовка
   разведён по-настоящему (`(reg & 0x1F) << 1` у DW3000 против `reg & 0x3F` у DW1000) — расхождение
   проявится на любом ненулевом регистре.
3. **Проверка ветви DW1000** сделана переключением флага в `uwb_config.h`, а не отдельной
   конфигурацией сборки в `.cproject` (её не заводили — владелец распоряжается конфигурациями; для
   постоянного удобства можно добавить конфигурацию `LAB09_DW1000` с `-D UWB_CHIP_DW1000`, если
   потребуется собирать обе без правки исходника).
4. **DW3000 потолок SPI** в `spistat` печатается как «7 МГц в INIT_RC, до 38 МГц в IDLE_PLL» — по
   DW3000 UM Table 4; фактический делитель по-прежнему даёт 1.5 МГц (годится обоим поколениям).

## Проверка на железе (владелец)

Прошить LAB09 (умолчание — DW3000) на оба кита, выполнить `devid` — ожидается `0xDECA0302` и
`verdict: OK - DW3000 alive (non-PDoA)` вместо прежнего «garbage». Проверить `spistat` (SCK 1.5 МГц,
mode 0, строка потолка DW3000). Путь DW1000 включается флагом `UWB_CHIP_DW1000`, когда будут модули.
